#### 5.1.2 用户操作矩阵

| 状态 | 可执行操作 | 禁用操作 | 备注 |
|------|-----------|---------|------|
| **Idle** | 添加/删除图片、调整参数、选择预设、开始 | — | 默认状态 |
| **Loading** | 取消、查看文件预览 | 所有编辑、参数调整 | 进度条可见 |
| **Processing** | 取消（atomic flag）、查看日志 | 列表操作、参数调整 | libvips 线程运行中 |
| **Success** | 添加新图片、关闭对话框、查看结果 | — | 显示"成功 N 张" |
| **Failed** | 重试失败项、放弃 | — | 显示错误码 + 详情 |
| **Cancelled** | 重试、放弃 | — | 清理临时文件 |

### 5.1.7 拼接合成预览（中间预览区）

> **本节是 5.1 拼接流程的扩展**：5.1.1-5.1.6 定义了"参数面板 + 拼接流程"，但中间预览区的"合成图交互"在 5.5 节（单图浏览）未覆盖。本节**专门定义拼接模式下的中间预览区**——合成图作为整体对象的操作模型。
>
> **与 5.5 节的关系**：5.5 是"单图浏览"状态机（Idle→Loading→View→Loading 循环），本节是"合成预览"状态机（Idle→Synthesizing→Ready→Highlighted），两者**互斥**——拼接模式下 5.5 的"上一张/下一张/双击全屏"被禁用。

#### 5.1.7.1 状态机

```
   ┌────────┐
   │  Idle  │ 列表为空（< 2 张可见项）
   └────┬───┘
        │ 列表有 ≥ 2 张可见项
        ▼
   ┌────────────┐
   │Synthesizing│ 200ms 防抖后正在重算合成图
   └────┬───────┘
        │ 合成完成（libvips 渲染完毕）
        ▼
   ┌────────┐
   │ Ready  │ 合成图就绪，可交互
   └────┬───┘
        │ 鼠标点击合成图上某区域
        ▼
   ┌────────────┐
   │Highlighted│ 高亮被点击的输入图
   └────┬───────┘
        │ 点击空白处 / Esc
        └───────┐
                ▼
           ┌────────┐
           │ Ready  │（回到 Ready）
           └────────┘
```

**5 个状态**：
- **Idle** — 列表为空或可见项 < 2（不满足 IMGPRO-2001 阈值）
- **Synthesizing** — 参数/列表变化触发重算，200ms 防抖
- **Ready** — 合成图渲染完成，可缩放/平移/点击
- **Highlighted** — 合成图上某输入图被选中（点击/双击后）
- **双击放大（Spotlight）** — 在 Highlighted 状态上双击，弹出放大查看器（独立 UI 层，不打断状态）

#### 5.1.7.2 实时合成触发

| 触发源 | 重算策略 | 防抖 |
|--------|----------|------|
| **列表变化**（增/删/排/隐藏切换） | 触发 Synthesizing | 200ms |
| **方向单选**（纵向/横向/网格/自定义） | 立即触发 | 0ms（单击即生效） |
| **间距滑块** | 触发 Synthesizing | 200ms |
| **背景选择** | 立即触发 | 0ms |
| **复选框**（保持宽度/去除白边/自动裁剪） | 立即触发 | 0ms |
| **颜色选择器**（自定义背景） | 选择完成后触发 | 200ms |

**防抖算法**：与 5.1.3 参数面板共用——最后一次变化后 200ms 才真正调用 libvips 渲染。多次快速调整只渲染一次。

#### 5.1.7.3 合成图渲染规格

```
┌─ 合成图渲染参数 ─────────────────────────────────────┐
│ 渲染分辨率    最大边 4096px（精细模式）              │
│                - 超过 4096px 的边等比缩放            │
│                - 短边按比例缩放                       │
│ 缩放策略      2C：自适应预览窗口                     │
│                - 默认：合成图缩放到预览区可视范围     │
│                - 留 32px 边距（不贴边）              │
│                - 用户可手动缩放覆盖自适应             │
│ 渲染线程     后台 QThread（与主 UI 线程分离）        │
│ 取消机制     atomic_flag（与 5.1.1 Processing 一致）  │
│ 缓存策略     按参数 hash 缓存最近 5 个合成图          │
│                - 列表/参数未变 → 直接读缓存           │
│                - 缓存命中 < 5ms                       │
│ 内存限制     单次合成图 ≤ 256MB（超限降级 2048px）    │
└──────────────────────────────────────────────────────┘
```

#### 5.1.7.13 异常分支

| 错误码 | 触发条件 | 用户提示 | 处理 |

```
┌─ 模式入口 ───────────────────────────────────────────┐
```

**章节小结**：
- 5.1.7 状态机（5 态）：Idle / Synthesizing / Ready / Highlighted / Spotlight
- 6 个核心交互：实时合成、边界标注、点击选中、虚拟按钮栏、双击 Spotlight、拖入预览区
- 沿用 5.5 缩放/平移，但禁用 5.5 的浏览类功能（上一张/下一张/双击全屏）
- 性能：200ms 防抖 + LRU 缓存 + 4096px 渲染上限 + 256MB 内存降级
- 异常：5 类错误码（2001/4003/4004/4005/1004）

- **测试**: Qt Test + GoogleTest + Google Benchmark
- **打包**: vcpkg 或 conan（libvips, libheif）
- **代码风格**: clang-format（Google 风格，4 空格缩进）
- **静态分析**: clang-tidy
- **CI**: GitHub Actions（Windows + macOS + Linux 三平台）

### A.1 状态机定义（State Machine）

**全局状态**：`ImageProController` 单例持有，所有 UI 组件订阅 `stateChanged(ImageProState)` 信号。

| 状态 | 触发条件 | 可执行操作 | 禁用操作 | 退出条件 |
|------|---------|-----------|---------|---------|
| `Idle` | 启动 / 上一次任务结束 | 添加/移除图片、调整参数、开始 | — | 点击"开始" → `Loading` |
| `Loading` | 点击"开始拼接/转换/压缩" | 取消 | 所有编辑、参数调整 | 文件全部就绪 → `Processing` |
| `Processing` | libvips 线程开始 | 取消（标记 `_cancelFlag`） | 列表操作、参数调整 | 全部完成 / 失败 / 取消 |
| `Success` | libvips 全部返回成功 | 添加新图片、关闭对话框 | — | 用户确认 → `Idle` |
| `Failed` | 任一文件失败 | 重试失败项 / 取消 | — | 用户确认 → `Idle` |
| `Cancelled` | 用户中途取消 | 重试 / 放弃 | — | 用户选择 → `Idle` |

**关键实现点**：

```cpp
// 取消标志必须 atomic，因为跨线程读取
class StitchTask : public QObject {
    std::atomic<bool> _cancelFlag{false};
public:
    void cancel() { _cancelFlag.store(true, std::memory_order_release); }
    bool isCancelled() const { return _cancelFlag.load(std::memory_order_acquire); }
};

// libvips 回调里检查（vips 8.12+ 支持 set_progress）
vips_image_set_progress(image, this);
g_signal_connect(image, "progress", G_CALLBACK(onProgress), this);
```

**反例警告**：❌ 不要在 `Processing` 状态允许修改参数，会导致 libvips 内部 buffer 与 UI 参数不一致，引发段错误或脏数据。

### A.3 libvips 选型对比（Proof of Choice）

| 维度 | libvips (推荐) | OpenCV | ImageMagick | stb_image |
|------|--------------|--------|-------------|-----------|
| 拼接 100×4K 耗时 | ~3.2s | ~18s | ~25s | 不支持拼接 |
| 内存峰值（100×4K） | ~450MB | ~3.2GB | ~4.5GB | OOM |
| 流式处理（无需全加载） | ✅ 天然支持 | ❌ | ⚠️ 部分 | ❌ |
| Windows 编译难度 | 中（vcpkg） | 中 | 高 | 低 |
| 并行加速 | ✅ 内置 OpenMP | ✅ | ⚠️ | ❌ |
| 格式支持 | 30+ | 20+ | 200+ | 10+ |
| 许可证 | LGPL-2.1 | Apache-2.0 | Apache-2.0 | Public Domain |
| C++ API 友好度 | 中（C API） | 高 | 低 | 高 |
| 社区活跃度 | 高 | 极高 | 中 | 中 |

**关键决策依据**：

1. **流式架构**：libvips 是 lazy evaluation，100 张 4K 不会全加载到内存
2. **性能**：拼接场景下比 OpenCV 快 5-6x，内存 1/7
3. **许可证**：LGPL 兼容商业闭源（动态链接 OK）

**集成方式**：
- 包管理：`vcpkg install libvips:x64-windows`
- CMake 集成：`find_package(Vips REQUIRED)`
- 备用方案：若 libvips 编译失败，回退到 OpenCV（需实现内存池）

**必须验证的坑**：
- ⚠️ Windows 上 `vips.exe` 依赖系统 `libstdc++-6.dll`，需打包进安装目录
- ⚠️ HEIC 格式需要额外 license，仅在用户启用时动态加载
- ⚠️ 大于 4GB 的图片需要 vips ≥ 8.12（启用 `VIPS_MAX_COORD=64`）

### A.4 大文件/批量场景架构

#### A.4.1 内存分块策略

```cpp
// 伪代码：分块拼接
const int CHUNK_HEIGHT = 1024; // 每次处理 1024 行
for (int y = 0; y < totalHeight; y += CHUNK_HEIGHT) {
    if (_cancelFlag.load()) break;
    auto chunk = vips_image_new_memory();
    // 仅加载当前 chunk 到内存
    vips_compose(chunk, ...);
    emit progress(y / totalHeight);
}
vips_image_write_to_file(chunk, outputPath, nullptr);
```

**内存预算公式**：
- 单图占用 ≈ `width × height × 4 bytes`（RGBA）
- 拼接 N 张最大图 → 内存 ≤ `max(单图) × 1.5`（含中间 buffer）
- 10 张 4K 拼接：3840×2160×4 × 1.5 ≈ 50MB ✅
- 100 张 4K 拼接：同上，仍是 ~50MB（流式优势）✅

#### A.4.2 列表虚拟滚动

- ❌ 禁止用 `QListWidget`：1000+ 项 FPS < 10
- ✅ 必须用 `QListView` + `QAbstractListModel` + `QListView::setLayoutMode(LayoutMode::Batched)`
- 缩略图懒加载：仅渲染可视区 + 上下 50px 预加载区
- 缩略图缓存：LruCache，key = `{filepath_hash}_{size}`，上限 200MB

#### A.4.3 进度算法

| 任务类型 | 进度计算方式 | 预估剩余时间 |
|---------|-------------|-------------|
| 单文件转换 | 字节进度 `vips_image_get_progress` | 滑动平均前 5 帧 |
| 多文件批量 | 加权 `Σ(已处理字节) / Σ(总字节)` | 同上 |
| 拼接 | 几何进度 `已拼行数 / 总行数` | 同上 |
| 压缩 | 字节 + 质量迭代次数 | 显示"迭代 x/N" |

**反例**：❌ 简单的"当前文件序号 / 总文件数"对大文件极不准确（1 张 4K 可能顶 100 张缩略图）。
